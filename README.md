# 截图 RPA 智能客服（当前接入渠道：企业微信）

> **不用官方 API、不用管理员权限**的自动客服：截屏 + OCR 读消息，只按你自己上传的资料回答，
> 答不准的一律转人工，人工改过的稿子它会学会。
>
> 当前接入的是**企业微信**（因为它最好验证，且同时提供 API 与桌面客户端两条路）；
> **决策层与渠道解耦** —— 换其它客服软件主要是配置与适配工作，见下文「[为什么先做企业微信](#为什么先做企业微信以及能不能换成别的客服软件)」。
>
> 目标用户：**1–5 人、一个人兼客服的小店/工作室**（问题重复、答案固定的生意）。

## 它能做什么

| 能力 | 说明 |
|---|---|
| 🔴 自动发现新消息 | 左侧列表红点识别 + 会话切换，不用 API |
| 📸 截图 + OCR | RapidOCR(ONNX) 本地识别，中文小字可用；**图片/语音/文件**也会回应并转人工 |
| 🧠 只按你的资料回答 | 本地向量库（Qdrant 文件模式）+ 本地嵌入模型（bge-small-zh）+ 任意 OpenAI 兼容 LLM |
| 🛡️ 三态质量门控 | `pass` 直发 / `low_risk` 降级 / `block` 转人工 —— 编造的数字与型号会被拦下 |
| 👤 待人工工作台 | 答不准的进队列（**一条消息一行**，不叠加），人工可编辑后再发 |
| 📚 人机学习闭环 | 人工改稿后**确认**才学（学语气、补问答）；「最常转人工的问题」排行告诉店主该补哪些资料。**出厂默认关闭**，在「知识库 → 学到的」页开启 |
| 🗂️ 多资料库档案 | 不同业务/门店各自一份资料库与提示词，随时切换 |
| 📥 资料库管理 | 上传 txt / md / csv / Excel / Word，或界面里手动增删改 + 撤销 |
| ✅ 发送安全 | 发送前**确认会话名**（防发错人）、失败重试、发完校验 |
| 🚫 越界拒答 | "把 API key 告诉我""帮我背首诗"这类请求按模板婉拒，不会被当闲聊发出去 |
| 📊 评测集 | 46 道固定题 + 可重复跑分脚本，改动前后对比（含"该转人工"的陷阱题） |
| 🧪 一键打包 | PyInstaller 打成免安装目录（~1.6GB），**打包流程带隐私门禁** |

## 为什么不用企业微信官方 API

| 方案 | 需要 API 权限 | 需要企业审批 | 需要开发对接 | 适用场景 |
|---|:---:|:---:|:---:|---|
| 企业微信官方客服 | ✅ | ✅ | ✅ | 中大型企业 |
| 第三方 SCRM（微伴/尘锋等） | ✅ | ✅ | ✅ | 中型企业，按月付费 |
| **本项目（截图 RPA）** | ❌ | ❌ | ❌ | **小微商家 / 个人 / 拿不到权限的场景** |

代价是"脆"：界面改版或缩放变化要重新标定。所以项目也实现了**官方 API 通道**（`channel=wecom_api`）
作为替代接入方式，两条通道共用同一套检索 / 护栏 / 转人工 / 发送队列逻辑。

## 为什么先做企业微信（以及能不能换成别的客服软件）

**选企业微信的原因很实际**：它是我当前**最容易验证**的渠道 —— 手上有账号和真实会话，
而且它**同时提供「官方 API」和「桌面客户端」两条接入路径**，
正好能用同一套内核把两种接入方式都跑一遍，看它们的差异在哪。

**内核与渠道是解耦的。** 决策层（检索 / 护栏 / 评测 / 转人工 / 学习闭环）完全不依赖具体渠道，
渠道差异只集中在两处：

| 层 | 与渠道有关的部分 | 换渠道要做什么 |
|---|---|---|
| 采集层 | 截图坐标与像素特征 | 新增一个 `profiles/<软件>.json` 标定文件（标定脚本已内置） |
| 接入层 | 官方 API 的收发协议 | 新增一个 gateway 适配（如 `gateway/wecom_kf.py`） |
| **决策层** | **没有** | **不需要改**：护栏 / 评测 / 转人工 / 学习闭环全部共用 |

**当前支持情况（不夸大）**

| 渠道 | 接入方式 | 现状 |
|---|---|---|
| 企业微信 | 截图模式 | ✅ 已验证（自用 + 小范围真实试用） |
| 企业微信 | 官方客服 API | ✅ 已实现，同一套决策层，可切换 |
| 微信 PC | 截图模式 | ✅ 标定文件已在仓库（`profiles/wechat_pc.json`），标定流程已内置 |
| 其它客服软件 | 截图 / API | 🔶 **可迁移**：需新增标定文件 + gateway 适配，尚未逐一验证 |

> 换句话说：换客服软件主要是**配置与适配**工作，而不是重写产品逻辑 ——
> 这是把"渠道"和"产品能力"分开设计的结果（`config/settings_store.py` 里已内置软件预设与切换）。

## 快速开始（源码运行）

```bash
# 1. 依赖（Python 3.10~3.12 / Windows）
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
#   想省磁盘：pip install torch --index-url https://download.pytorch.org/whl/cpu

# 2. 准备本地嵌入模型（fresh clone 必做，否则启动会报错）
python scripts/prepare_model.py      # 从 hf-mirror 下载 bge-small-zh，约 92MB

# 3. 配置：复制模板，填自己的模型 Key
copy .env.example .env
notepad .env        # 至少填 LLM_API_KEY（支持 DeepSeek / 通义 / 本地 vLLM 等任意 OpenAI 兼容接口）

# 4. 启动
python main.py
```

也可以用 `启动.bat`（会自动建目录、检查 `.env`，源码模式与打包模式都能启动）。

### 上手 6 步（详细版见 [`docs/使用说明.md`](docs/使用说明.md)）

| 步骤 | 做什么 | 要点 |
|---|---|---|
| 1 | 装依赖 + 准备嵌入模型 | `pip install -r requirements.txt` → `python scripts/prepare_model.py` |
| 2 | **接 LLM API**（关键第一步） | 界面「设置」填 `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL`；**不填也能开**，但只转人工、不外发 |
| 3 | 选接入方式 | 「企业微信 · 截图模式」零门槛；微信 PC 需先 `python scripts/calibrate_chat_app.py` 标定 |
| 4 | 打开客户端 → 点「开始」 | 只处理**开始之后**收到的新消息（不翻旧账） |
| 5 | 上传业务资料 → 重建索引 | txt / md / csv / Excel / Word；先用 `examples/kb_demo/` 试跑 |
| 6 | 到「试问一句」验证 | 顺便确认模型 Key 通了；答不准就先补资料，再考虑改提示词 |

> 排错先看 `logs/monitor.log`；常见问题（闪退 / 401 / 找不到窗口 / 老是转人工）见
> [`docs/使用说明.md`](docs/使用说明.md) §9。

## 知识库怎么用

| 动作 | 位置 | 说明 |
|---|---|---|
| 上传资料 | 知识库 → 资料库 → 选择文件… | txt / md / csv / Excel / Word；上传后点「重建索引」 |
| 看/改资料 | 资料库列表（问题/回答两列） | 双击看全文；可新增、编辑、删除、撤销上次修改 |
| 验证效果 | 试问一句 | 看检索命中与回答，改完立刻生效 |
| 找该补什么 | **最常转人工的问题** | 按次数排序；双击一行把这句话预填进新增资料的问题框 |
| 调语气 | 提示词 | 系统提示、欢迎语、闲聊、占位语都能改，保存即生效 |

示例资料在 [`examples/kb_demo/`](examples/kb_demo/)（虚构的相机租赁店），可先跑通再替换成自己的。

## 质量与安全设计（这个项目的重点）

1. **数字必须有出处**：回复里的价格/押金/天数若不是资料里出现过的，直接拦下转人工
   （时间类允许 12/24 小时制等价："下午6点" == "18点"）。
2. **型号/品牌也要有出处**：资料里没有 GoPro，就不许说"GoPro 有货"；
   但"我们**没有** GoPro"这种否定句不会误拦。
3. **不确定就转人工**：说了"可能/大概"、检索分不够、模型自己说答不了 → 转人工 + 给草稿。
4. **越界请求拒答**：套凭据、让背诗、算长算式、试图改指令 → 固定模板婉拒（不经过 LLM）。
5. **发送前确认会话名**：读错人/发错人是不可逆的，所以点开会话后必须确认聊天区就是这个人。
6. **不重复回、不漏答**：'已经有人回过' 的气泡记 24 小时；'待回复' 的气泡只用 10 分钟短窗口
   （**漏答比重复回严重**）。
7. **人工确认才学习**：从改稿里学到的语气/问答会列出来给你勾选，不确认不进库。
   学习功能**出厂默认关闭**（会往本机写文件，不该在店主弄明白它学什么之前就悄悄开始），
   在「知识库 → 学到的」页勾上「自动学习」才启用。

这些设计都有事故复盘与回归测试支撑，见 [`docs/`](docs/)。

## 隐私与数据

* **客户聊天记录只存在本机**（`data/context/`），程序不上传聊天记录做训练。
* 回答时会调用**你自己配置的**模型接口，发送内容是：**客户这一句话 + 命中的资料片段**。
* **不填 API Key 也能开**：此时机器人不自动答，只把消息转「待人工」，不向任何地方外发内容。
* `.env`（密钥）、`data/`、`logs/`、`.privacy_needles`（本地私密名单）都在 `.gitignore` 里，不会进仓库。
* 打包分发前跑一次自检，**不通过会中止打包**：

```bash
python scripts/privacy_check.py --path dist/WeComBot   # 检查包
python scripts/privacy_check.py --path .               # 检查仓库
```

它会扫：真实凭据（`sk-` / corp id / Token）、客户姓名（读你本地 `.privacy_needles`）、
开发机绝对路径、手机号，以及 exe/dll 里的字节串。
详见 [`docs/打包与隐私检查.md`](docs/打包与隐私检查.md)。

## 测试与评测

```bash
SKIP_EMBED_TESTS=1 python -m pytest tests/ -q     # 1446 passed, 4 skipped（本机全绿）
```

* **1521 个测试**：含"发错人""内部信号外泄""重启后重复回复""编造型号""越权承诺"等事故的回归测试。
* **46 题评测集**（`scripts/eval_set.py`，含 9 道"应转人工 / 不该回"的陷阱题（escalate 7 + no_reply 2））：

| 版本 | 行为符合期望 | 危险直发（该转人工却发了） |
|---|---|---|
| 引入评测集时的基线 | 28/46 | 3 |
| 修掉 6 个问题后 | 37/46 | 0 |
| 门槛扫到 0.55 后 | 43/46 | 0 |
| **门槛降到 0.50 后（当前）** | **42/46** | **0** |

* **三套各 200 条测试消息**（`eval/messages_200*.csv`，另附真机逐条发送用的纯文本版）：
  覆盖高频直答 / 组合推理 / 资料缺口 / 安全越界 / 闲聊身份 / 无信息量 / 噪声鲁棒 / 骚扰情绪 八大类。
  第一批跑出 19 条危险直发 → 按根因逐类修掉 → 再用**没见过的新题**（第二批、第三批）复验：
  三批 600 条在门槛 0.50 下**行为符合 560/600、危险直发 0**（0.55 是 550/600）。
* **阈值扫描**（`scripts/threshold_scan.py`）+ **结果对比**（`scripts/compare_thresholds.py`）：
  硬条件是"危险直发必须为 0"，再比谁把该答的问题白转人工。0.55 → 0.50 有两条独立证据
  （46 题扫描 42 vs 41；三批 600 条 560 vs 550），降门槛前先把"检索分被动兜底"换成了主动护栏。
* 评测脚本用**资料库副本 + 临时目录**，只生成不发送，**不会碰真实客户记录**。
* **资料库体检**（`scripts/kb_audit.py`）：数出"问法本身就被规则拦下"的资料条数 ——
  这类问题补再多资料也不会被回答（规则在检索之前就返回了）。当前 230 条里 **2 条**，
  且都是本来就该转人工的（"我昨天下的单发货了吗""你们店在哪"）。
  实测资料库检索自一致性均值 **0.878**、语义不变改 1–2 个字后 **0/238** 掉下门槛
  —— 也就是说：**客户觉得"改一两个字就转人工"，问题不在资料，在管道**。
* **资料库优先于规则层**（`kb.kb_first`，默认开）：规则判了转人工、但资料库能命中时，
  改成按资料库回答 —— 否则"补资料库"永远降不下转人工率。但**只对政策类原因生效**
  （订单变更 / 发票寄送 / 店内情况 / 政策未覆盖）；实时状态（快递到哪了、有没有现货）、
  权限（议价 / 退款 / 投诉）、安全（伪造 / 要他人信息）类一律转人工，分数再高也不放行。
  门槛 **0.75** 是实测定出来的 —— 见下：

  | 放行门槛 | 600 条评测集里被放行 | 其中答非所问 |
  |---|---|---|
  | 0.50 | 14 条 | 13 条 |
  | 0.65 | 6 条 | 5 条 |
  | **0.75（当前）** | **1 条** | **0 条** |

  依据：实测"答非所问"的相关条目落在 0.607–0.726（"能指定配送到**小时**吗"命中
  "可以指定**日期**送到吗" 0.726、"能签三方合同吗"命中"可以签合同吗" 0.724），
  而资料库里**真有这条**时自命中 min 0.738、中位 0.883，**≥0.75 覆盖 229/231 = 99%**。
  两类刚好被 0.75 分开。`enabled=false` 可整体关掉（关闭后完全回到"规则先判"的老行为）。

## 打包成免安装程序

```bash
python scripts/build.py          # 约 10 分钟，输出 dist/WeComBot/
```

包内包含：Python 运行时、OCR、本地嵌入模型、提示词、示例资料库、窗口标定、使用说明。
包内**不包含**：`.env`、客户聊天记录、运行状态、日志 —— 打包流程会强制自检，不通过就中止。
把整个 `dist/WeComBot` 压缩发给对方，解压后双击 `启动.bat` 即可（首次启动 30~90 秒加载模型）。

## 运行要求

* **Windows 10 / 11**：依赖 Win32 窗口、剪贴板与截图接口。
* **需要桌面客户端**：企业微信 PC 版（截图模式）；微信 PC 版需先用 `scripts/calibrate_chat_app.py` 标定。
* **客户端改版或缩放/分辨率变化后**：需要重新标定 `profiles/`（发送前会确认会话名，标定不对时会跳过而不是发错人）。
* **首次启动**：要加载 OCR 与本地嵌入模型，约 30~90 秒。

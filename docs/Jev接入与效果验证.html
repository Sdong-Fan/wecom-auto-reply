Jev 接入与效果验证

一次「把新模型引入现有系统」的完整过程 ｜ 相机租赁客服机器人 ｜ 2026-10

一句话结论：我评估了 Jev（TypeSafe 的决策模型），用自有评测集量了两个候选落点 —— 否决了其中一个，在另一个上量化出了真瓶颈（基线 72.7%）， 并把方案以「默认关闭、只有否决权、失败自动降级」的方式接进系统，对照实验进行中。

1. Jev 是什么（为什么值得评估）

  • 它是判断模型，不是生成模型：只回答选择题 / 打分 / 是非，返回概率，不生成文字。 这是它近期受关注的原因 —— 通用大模型做分类与路由又贵又不稳，专用判断模型在窄任务上更省更准。
  • 接口：POST https://jev.bocha.cn/v1/systemone，模型 bocha-jev-v1， 一次请求可带全部题目（加题不加价），单次约 1000 输入 token、约 1 秒。
  • 返回的是概率（noul = 命题为真的程度），可以直接当置信度与阈值用。

2. 我没有直接接 —— 先量两个候选落点

我的链路里有两个位置"看起来像判断问题"，我都用自有评测集量过，没有靠感觉选：

100%落点①「该不该答」：规则层在 600 条标注上全对
72.7%落点②「资料覆盖没覆盖」：现状用相似度当代理
进行中落点②的 Jev 对照实验
落点现状靠什么实测结论
① 该不该答 词表 + 正则 规则层 600/600（100%）；34 条"不该回"全是表情/符号/收尾语 否决——低熵问题，正则已满分，判断模型不可能更好
② 资料覆盖没覆盖 检索相似度分数 > 0.50 322 条干净标注上只有 234/322（72.7%），87 条假阳性 这才是该上的地方：相似度 ≠ 可答性
落点②的具体表现：这些消息和资料库语义高度相关、检索分很高，但资料里没有那个事实： 现在店里有几台A7M4（0.653，实时库存）、A7M4 80一天行吗（0.728，议价）、 我的快递单号发我（0.528，订单物流）、你们发错货了（0.542，售后纠纷）、 支持分期吗（0.532，未覆盖政策）。
这是 RAG 最经典的失效模式：相似度不等于可答性（similarity ≠ answerability）。 它也解释了我的架构现象 —— 为什么护栏越加越多：上游"能不能答"的判断是错的， 所有"不该答"只能堆到下游用词表兜。把判断模型放在这里，是把兜底前置。

3. 怎么测的（评测集与口径）

  • 数据来源是真实语料：我先把自己接待过的 77 条真实客户消息做了分类（99% 集中在 7 类问题）， 再按这个分布和资料库覆盖范围出题 —— 46 题关键路径「尺子」+ 3×200 条「体检」（8 大类）。
  • 322 条干净标注用于覆盖维度：大类「高频直答（资料库有答案）」196 条 → 覆盖； 「资料缺口（应转人工）」126 条 → 未覆盖。
  • 判分口径：脚本只判"行为对不对"，内容对错我看原文 —— 不让脚本自己判内容质量。 标注是我做的、不是独立标注，所以只用于客观维度。

4. 接入设计（三条硬约束）

  1. 默认关闭的三态开关（config.json → judge.engine）： rules（默认，线上现状，不联网）/ shadow（影子：规则决定行为， 同时问一次 Jev 只落日志取证，零风险）/ jev（灰度：Jev 决定）。
  2. Jev 只有否决权，没有放行权：它说"不必回"就拦下；说"要回"仍然要过检索、护栏、阈值三关 才能发出去。它永远不能凭一句话让回复发给客户 —— 判错方向不对称时，这是唯一安全的接法。
  3. 失败一律降级：超时 / 报错 / 没配凭据 / 返回结构不对 → 自动退回规则层。 判断模型不能成为接待的单点故障。
  • 分级调用保护延迟：只在规则层说"要回"时才问 Jev（规则说不用回的本就不生成）， 避免把 1.5 秒的中位响应拉到 2.5 秒。
  • 隐私默认最小：只发客户当前这一句，不发历史；只有"判覆盖"那道题必须带上检索片段（否则模型只能靠世界知识猜）。
  • 题目按业务语域重写：官方的题集是社交场景的，照抄必错。我按客服语域写了 4 道 （该不该答 / 意图 / 是否只有店主能定 / 资料是否覆盖），instructions 一律英文（判断模型主训练语言）。

6. 为什么现在暂不实装

  1. 只有基线，还没有对照：没有对照就不能说它更好。
  2. 题目没经过校准：还没按判断模型的脚手架做标注集校准（命中率 / 打分误差）。
  3. 隐私口径要业务方确认：接它意味着每条客户消息发到固定的第三方端点， 和我"对话不出本机、只发给店主自己配的接口"的口径冲突。
  4. 判错方向不对称：判"覆盖"其实没覆盖 → 会拿错资料答，不可逆。所以要先在影子模式攒够证据。
  5. 阈值不会消失：它给的是概率，还是要定"概率 > 多少才覆盖"，只是换了对象。
  6. 它不是当前最紧的事：600 条里那 30 条"该答没答"有三处根因，判断层只能解决其中一部分。
推进顺序（先证明它更好，再让它碰客户）：
影子模式取证 → 用 322 条标注集证明打过 72.7% → 只在自己号上灰度 → 同一套尺子（46 题 + 3×200 条）复核不退化 → 才谈上线。
验收线：判断命中率 ≥ 70%，且危险直发仍为 0。

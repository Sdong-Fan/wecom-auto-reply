# 事故记录：回复错人 + 把内部信号发给客户

时间：2026-09-26 21:48 ｜ 现场：`logs/monitor.log`、`logs/auto_replies.jsonl`

## 现象

店主在「客户A@微信」里问「老板你多大了」，结果：

1. **很久没回应**：机器人确实生成了占位语「帮您问下老板的年龄，稍等。」，但
   **发送被拒**（`sent: false`），客户一个字都没收到。
2. **回错人**：4 秒后同样一句「帮您问下老板年龄，稍等哈。」发到了
   **客户B@微信** 那里 —— 而 客户B 根本没问过这句。
3. **回了错话**：店主在待人工页点了「发送」，客户收到了 **「需要人工处理」** 六个字。

## 根因（三个独立问题）

### 1. 点开某一行就直接读聊天区，从不确认"打开的到底是不是这个人"

```
21:48:02 兜底行0 y=129 对话名: [客户A@微信 老板你多大了 刚刚]  → A 问的
21:48:10 发送 A 的占位语 → 校验不通过（顶部读到 客户B @微信）→ 拒绝发送 ✓（防护生效）
21:48:39 待人工页人工点了发送「需要人工处理」→ 发给了 A
21:48:41 兜底行1 y=223 对话名: [客户B@微信 …] → 点开 → OCR 读到「老板你多大了」
```

21:48:41 那一步是**翻车现场**：点了 y=223（客户B 那行），但聊天区还停在
客户A 的会话没刷新，于是**把 A 的消息算成了 客户B 问的**，占位语就发给了 客户B。

会话列表还会因为新消息**重新排序**（日志里 21:48:51 就看到 客户B 跑到了 y=129），
按 y 定位本来就不稳。

**为什么发送路径有校验、扫描路径却没有**：发送路径的代价被想清楚了
（"宁可不发也不能发错人"），但*读*这一侧没有被同等对待 —— 读错了只是
"回答别人的问题"，看起来不严重，实际上生出来的回复会发错人。

### 2. 「需要人工处理」既当内部信号、又当客户回复

`prompts/system.md` 里写着"知识不足时唯一正确回复是「需要人工处理」"，
model 照做了；而代码把 `reply_text` 原样塞进待人工队列当草稿。
店主看到草稿、点「发送」→ 客户收到这六个字。

这是**设计缺陷**：一个字符串同时承担"给程序看的信号"和"给客户看的话"两种角色。

### 3. 发送确认失败就彻底放弃，不重试

`_do_send` 里 `open_conversation` 一次不成功就 `return False`。
当时会话列表正在重排（店主刚手动发过消息），第一次找错行很正常 ——
一次失败就放弃，客户那边就一直没收到，表现成"很久才回复"。

## 修法

| 问题 | 修法 | 位置 |
|---|---|---|
| 读错人 | 点开后先 `confirm_opened()` 确认聊天区**就是这个人**，读不到别人的名字才继续；读到别人 → 跳过这一行、不读不回，冷却 30 秒 | `wxbot/scanner.py`、`main.py` 两条扫描路径 |
| 信号外泄 | ① LLM 说"答不了"时草稿置空 ② `llm_requests_human` 时**绝不自动发送** ③ 待人工页发送前再拦一次 | `rag/responder.py`、`main.py`、`gui/main_window.py` |
| 一次失败就放弃 | `open_conversation` 失败等 1.2 秒再试一次，两次都不成才放弃 | `main.py::_do_send` |

### confirm_opened 为什么分三态

`verify_open` 只回 True/False，分不清**"读到了别人"**和**"根本没读出来"**。
这两者处理必须不同：

* `mismatch`（读到别人的名字）→ 点错了或列表在动，**不能**把内容算到这个人头上
* `unknown`（读不出名字）→ 能力问题，退回原来的行为（不能因为读不出就不干活）

只按 `mismatch` 拦，是为了不把"OCR 退化"变成"机器人罢工"。

## 回归测试

* `tests/test_wechat_safety.py::test_human_marker_is_never_a_draft`
* `tests/test_wechat_safety.py::test_human_marker_detector`
* `tests/test_send_target_lenient.py::test_both_sites_use_the_shared_matcher`
  （三处调用都走同一个匹配器，松紧一致）
* `tests/test_pending_no_stack.py`（同一人不叠加）

## 还没解决的（已知）

* **列表重排**这件事本身没根治：现在是"点开后确认"，确认不过就跳过。
  更好的做法是用名字作为行标识（`wxbot/new_message_tracker.row_key` 已经在做），
  扫描路径的定位还没完全切过去。
* 占位语是**第二次 LLM 调用**（回复一次、占位语一次），每次转人工多花 1~2 秒。
  可以并行发起或改成模板，但会牺牲一点自然度。

# 事故二：同一个问题回了客户两遍

时间：2026-09-26 21:45 与 21:59 ｜ 现场：`logs/monitor.log`

## 现象

客户B 在 21:45 发了一句「调戏一下Ai 哈哈哈哈 有卖什么东西 1+2*3-1=多少」，
机器人 21:45:25 已经回过「帮您确认下卖什么和这道算式，稍等。」。
**14 分钟后（21:59:40）它又回了一遍**：「我先去确认下咱们卖什么，稍等哈。」

## 根因（三个叠在一起）

1. **「这条已经回过」只存在内存里**（`MessageDetector._seen_messages`）——
   21:59:08 重启过程序，记忆清零
2. **有效期只有 300 秒**（`message_dedup_seconds`）—— 21:45 到 21:59 是 840 秒，
   就算不重启也已经忘了
3. **记的是整段合并文本**（几个气泡用空格拼成一段）—— OCR 只要多读进一个新气泡，
   整段就对不上，于是"旧气泡 + 一个新气泡"被当成全新消息，把老问题再回一遍

## 修法

| 改动 | 说明 |
|---|---|
| 「已处理消息」落盘 | `data/state/seen_messages.json`，启动时读回；写入节流 2 秒 |
| 精确匹配用**长 TTL** | 新增 `seen_message_ttl_seconds`（默认 24 小时）。同一句话回过一次就别再回（**后来改成分层两本账，见「事故四」**） |
| 模糊匹配仍用**短窗口** | 保持 300 秒。窗口太长会把"有货吗"和"A7M4 有货吗"这种真·追问吞掉 |
| **逐条气泡**判断 | `unseen_texts()`：从一堆气泡里挑出没处理过的；全都被回过 → 直接跳过（不回、不转人工、不进待人工） |
| 处理完逐条记已见 | `mark_messages_seen()`，下次才滤得掉旧气泡（只记合并文本没用） |

两条扫描路径（红点 + 兜底）都改了；`_scan_fallback` 的返回值多带一项"这条消息的气泡文本"。

## 边界

* 另一个客户说同样的话 → 不受影响（记录按客户隔离）
* 同一个客户隔天再问同一句 → 超过 24 小时，会正常回答
* 太短的文本（<3 字）和太短的模糊匹配（<4 字）不做去重 —— 免得把新问题当成重复

## 回归测试

`tests/test_reply_once.py`（21 个）：重启不忘、长 TTL、短窗口不被拉长、
逐条过滤、另一个客户不受影响、超期后能再回答。

# 事故三：同一句话回了客户两遍（人工回过也算回过）

## 现象

客户B 21:45 问了一句，机器人 21:45:25 已经回过；**14 分钟后（21:59:40）又回了一遍**。
同一类问题还有：店主自己在企微里手动回过之后，机器人还会再插一句"稍等"。

## 根因

1. 「这条已经回过」只存在内存里（`MessageDetector._seen_messages`）—— 重启就忘
2. 有效期只有 300 秒 —— 840 秒前的记录已经不算数
3. 记的是**整段合并文本** —— OCR 多读进一个新气泡，整段就变了
4. `extract_unreplied_bubbles` 里遇到蓝泡直接 `break`，**根本看不到蓝泡之上的客户气泡**，
   所以"人工回过"这件事从未被记住

## 修法

| 改动 | 说明 |
|---|---|
| 「已处理消息」落盘 | `data/state/seen_messages.json`，启动读回，写入节流 2 秒 |
| 精确匹配用**长 TTL** | `seen_message_ttl_seconds`，默认 24 小时（**后来改成分层两本账，见「事故四」**） |
| 模糊匹配仍用**短窗口** | 300 秒，免得把"有货吗"和"A7M4 有货吗"这种真·追问吞掉 |
| **逐条气泡**判断 | `unseen_texts()`：挑出没回过的；全回过了 → 跳过（不回、不转人工、不进待人工） |
| **人工回过也算回过** | 新增 `extract_bubbles_detail()`，返回"蓝泡**之上**的客户气泡"；两条扫描路径把它们 OCR 后记为已见（上限 5 条，只挑最靠近蓝泡的） |

**踩到的坑**：`bubbles` 是**从下往上**收集的，蓝泡最先遇到。原来那里 `break`，
所以蓝泡之上的气泡永远看不到 —— 这就是"人工回过"一直没被记住的直接原因。
改成不 `break`、只按 `newest_blue_top` 分类。

顺带修掉一个真 bug：Windows 上 `time.time()` 只有约 15ms 精度，
同一秒内连着入队的待人工条目**时间戳完全相同**，"哪条是最新的"变成随机的
（同一客户连问两句，点「发送」可能发的是旧那条）。改成按递增 `seq` 排序。

## 边界

* 另一个客户说同样的话 → 不受影响（记录按客户隔离）
* 同一个客户隔天再问同一句 → 超过 24 小时，正常回答
* 太短的文本（<3 字）不做去重；模糊匹配只对 4 字以上生效
* 「已回复」的气泡只 OCR 最靠近蓝泡的 5 条 —— 再往上的老消息不值得花 OCR

## 回归测试

* `tests/test_reply_once.py`（21 个）
* `tests/test_already_replied.py`（11 个）：真画一张假聊天区（灰泡+蓝泡），
  验证"蓝泡之上的客户气泡被认出来"、"蓝泡之下新追问仍算未回复"、
  "两条路径都真的记了已见"、"OCR 炸了不影响扫描"

# 事故四（设计修正）：一本账管不了两件事 → 分成两本

时间：2026-09-27 ｜ 现场：代码审计

## 现象（两个方向相反的抱怨）

* **漏答**：客户 10:00 问「有货吗」，机器人回过了；11:00 他又问一次同样的
  五个字 —— 因为"精确匹配用 24 小时长 TTL"，这句被当成"已经回过"，
  **一声不吭**。
* **重复回**：21:59 那次反过来 —— 长记忆被 `clear_seen()` 顺手剪掉，
  重启后重读到的旧气泡又回了一遍。

同一个 `_seen_messages` 字典，两件事都要它干，结果怎么调都是错的。

## 根因

| # | 问题 | 说明 |
|---|---|---|
| 1 | 「待回复」和「已回过」共用一本账 | 前者要短窗口（**漏答比重复回严重**），后者要长记忆（防重启重读）。窗口只有一个，必然顾此失彼 |
| 2 | `clear_seen()` 按 300 秒剪 `_seen_messages` | 每次自动回复成功后都调它 —— 于是刚记下的"已回过"如果超过 5 分钟，会被一并抹掉。21:59 重读能成功，这是原因之一 |
| 3 | 时间数字被误判成"编造" | 资料写「18 点下班」，模型答「下午 6 点下班」→ 字面比 18≠6，白转人工 |

## 修法

| 改动 | 说明 | 位置 |
|---|---|---|
| **两本账** | `_seen_messages`（短窗口，管"待回复"）+ `_replied_seen`（24h，管"已经有人回过"）。后者只由 `_mark_already_replied` 写 | `wxbot/detector/_message_detector.py` |
| `long_term` 参数 | `is_message_seen(..., long_term=True)` 默认走长记忆（查重、防重记）；`unseen_texts(..., long_term=False)` 默认走短窗口（挑待回复的气泡）。主路径三处去重判断显式传 `long_term=False` | 同上 + `main.py` |
| `unreplied_dedup_seconds`（默认 600） | 「待回复」气泡的短窗口，可配 | `config.json` |
| `clear_seen()` 只清短窗口那本 | 长记忆按 `seen_message_ttl_seconds` 保留 | 同上 |
| 落盘加 `replied` 段 | 重启后长记忆照旧生效 | `data/state/seen_messages.json` |
| 时间数字 ±12 等价 | 只对"**每一次出现都是时间**"的数字放宽（`_time_equivalent_grounded`）。"日租 6 元，晚上 6 点"里的 6 元照样从严 | `rag/guard.py` |
| 会话历史按人归一 | OCR 名字读法不同（`@微信` 读丢）会把一个人的历史切成好几份 → `ContextStore` 用 `same_person` 归一，读到多份就合并（**返回活下来的那份**，行多的当主文件） | `rag/human_fallback.py` |

## 边界

* 「已经有人回过」的气泡：24 小时内不再回（重启也不忘）
* 「待回复」的气泡：600 秒内不重复处理；超过之后客户再问同样的话，**正常回答**
* 另一个客户说同样的话 → 不受影响（两本账都按客户隔离）
* 补过资料库又转人工的问题会自动退回「待补」（见「最常转人工的问题」）

## 回归测试

* `tests/test_reply_once.py`：短窗口过了能再答、长记忆扛得住重启、
  `clear_seen` 不抹长记忆、主程序三处都传 `long_term=False`
* `tests/test_guard.py`：12/24 小时制等价放行、价格数字照旧从严、
  同一数字既在时间里又在价格里时不放宽
* `tests/test_context_merge.py`：同一个人的几种名字写法只留一份文件、
  读回时合并且**返回活下来的那份**、别的客户不受影响

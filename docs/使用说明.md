# 使用说明（从零到能自动回复）

> 面向：第一次把这个项目跑起来的人。
> 打包版用户：解压后直接看包里的 `使用说明.txt`，那是这份的简版。
> 预计：**20–40 分钟**（其中模型与依赖下载占大头）。

---

## 0. 前置条件

| 项 | 要求 |
|---|---|
| 系统 | **Windows 10 / 11**（采集层依赖 Win32 截图、剪贴板、窗口接口） |
| Python | **3.10 ~ 3.12**（3.13 未验证） |
| 客户端 | 企业微信 PC 版；或微信 PC 版（需先标定） |
| 模型 Key | 任意 OpenAI 兼容接口（DeepSeek / 通义 / 本地 vLLM…）。**不填也能开**，见 §3 |

---

## 1. 装依赖

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

> 想省 ~2GB 磁盘：`pip install torch --index-url https://download.pytorch.org/whl/cpu`
> （本项目不用 GPU）
>
> 国内网络慢可以加镜像：`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`

---

## 2. 准备本地嵌入模型（**fresh clone 必做，否则启动会报错**）

```bat
python scripts/prepare_model.py
```

* 会从 `hf-mirror.com` 镜像下载 `bge-small-zh-v1.5`（约 92MB）到 `bge_model/`
* 完成后 `bge_model/model.safetensors` 应该存在
* 能直连 HuggingFace 的话：`python scripts/prepare_model.py --official`

> **为什么单独一步**：`bge_model/` 不进仓库（太大），而程序默认 `HF_HUB_OFFLINE=1`
> （避免启动时联网校验卡 10 秒）。既没有本地目录、缓存里也没有 → 启动时就崩在加载嵌入模型这一步。

---

## 3. 接 LLM API（**关键第一步**）

### 方式 A：界面里填（推荐）

1. `python main.py` 或双击 `启动.bat`
2. 右上角「**设置**」→ 模型接口
3. 填三项，保存：

| 字段 | 填什么 | 例子 |
|---|---|---|
| `LLM_API_KEY` | 你的模型 Key | `sk-xxxxxxxx` |
| `LLM_BASE_URL` | OpenAI 兼容地址 | DeepSeek：`https://api.deepseek.com/v1` |
| `LLM_MODEL` | 模型名 | `deepseek-chat` |

填完点「**测试连接**」，当场就知道对不对（通了 ✓；不通会说明是密钥不对、模型名不对还是地址不通）。

> **密钥框第一次是空的，这是正常的。**
> 第一次运行 `启动.bat` 会从 `.env.example` 复制出一份 `.env`，里面那把 `sk-your-deepseek-key`
> 是**示例占位符、不是密钥**，程序会把它当作"没填"（不会拿它去调接口、也不会显示在密钥框里）。
> 界面下方会标出配置文件的完整路径，方便确认"这个密钥是从哪个文件读的"。

### 方式 B：直接改 `.env`

项目根目录的 `.env`（不存在就从模板复制：`copy .env.example .env`）：

```ini
LLM_API_KEY=sk-xxxxxxxx
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
```

> 也兼容旧键名 `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL`（三项留空时回落到它）。
> 密钥只写在本机 `.env`，不会进仓库、不会进打包产物。

### 不填 Key 会怎样？——**不允许「开始」**（这是刻意设计）

程序**照样能启动、能识别消息、能建资料库**，但**点「开始」会被拦下**，并弹窗送你到「设置」。
界面顶部也会常显一条红字提示。没配好模型接口，它不会替你接待客户。

**为什么这么设计**（这是实测踩出来的）：

不填 Key 时，机器人**并不是"完全没动作"** —— 下面三类根本不需要联网调模型，照样会发给客户：

| 客户问的 | 不填 Key 时的行为 | 要联网调模型吗 |
|---|---|---|
| "现在几点""今天几号" | **真答案**（读本机系统时钟） | ❌ 不用 |
| 要凭据 / 让你算长算式 / 让你背诗 | **固定模板婉拒**（"这个我帮不上忙哈～"） | ❌ 不用 |
| 其它任何问题（价格、库存、政策…） | 转人工，并**自动回一句固定占位语**（"好的，我帮您问一下细节，稍等片刻就回复您～"） | ❌ 不用 |

也就是说：**每一条答不了的消息，客户都会收到"稍等，我帮您确认一下"**。
如果店主以为"没填 Key 就等于停着"而挂着不管，客户就是**被许诺了一个不会到来的回复**——
比一开始不出声更糟。所以现在的做法是**从一开始就不让它跑起来**。

> 想先观察它的判断而不打扰任何客户？程序默认就是「未启动」，打开后什么都不做。
> 但要真正跑起来接待，必须先配好模型接口。

### 怎么确认 Key 通了

界面「知识库 → **试问一句**」问一个资料库里有的问题（如 `索尼 A7M4 日租多少钱`）：
* 有回答 → Key 通了
* 报模型相关错误 → Key/地址/模型名有问题（**日志**里会写具体错误，见 §9）

## 4. 选软件与接入方式

「设置」里选一个：

| 选项 | 说明 |
|---|---|
| **企业微信 · 截图模式** | 零门槛：不要 API 权限、不要开发对接。**先用这个跑通** |
| **企业微信 · API 模式** | 官方客服 API，需要企业认证 + 回调服务（见 §8），门槛更高 |
| **微信 PC · 截图模式** | 先标定：`python scripts/calibrate_chat_app.py`，生成 `profiles/wechat_pc.json` |

> 三种模式**共用同一套**资料库检索、质量护栏、转人工与学习闭环 —— 换模式不用改产品逻辑。

---

## 5. 打开客户端 → 点「开始」

1. 登录**企业微信 PC 版**（或微信 PC 版），让窗口处于可见状态（最小化到托盘会读不到）
2. 界面点「**开始**」
3. ⚠️ 它**只处理「开始」之后收到的新消息**（不翻旧账）—— 这是刻意的，避免一上来就把历史消息全回一遍

---

## 6. 建资料库（决定它答得准不准）

「知识库」→「**资料库**」：

1. 「选择文件…」上传：**txt / md / csv / Excel / Word** 都支持（可以上传多个）
2. 点「**重建索引**」（首次要加载嵌入模型，约 10–30 秒）
3. 到「**试问一句**」验证：它会显示命中的资料与生成的回答

没有资料时想先试跑：上传 `examples/kb_demo/` 里那 14 个 txt（虚构的相机租赁资料）。

**三条使用建议**（来自真实使用）：
* 问题写成客户**真的会问**的那句话（检索才容易命中）
* 回答里的**价格、押金、天数**必须真实 —— 机器人只按资料回答，资料里查不到的数字它会转人工
* 资料改了要**重新重建索引**，否则检索还是旧的

---

## 7. 调说话方式（提示词）

「知识库」→「**提示词**」：系统提示、**欢迎语**、闲聊、占位语都能改，保存即生效。

* 欢迎语：第一次跟某个客户说话时先招呼一句（可关）
* 占位语：转人工时发给客户的「我去确认一下」
* 语气样本：让它学你店里的说话方式（不是装人，是像你）

⚠️ **占位符别改名**：`{context}`、`{conversation_history}`、`{tone_samples}` 是程序往里填内容的
位置。写成别的花括号（比如 `{contex}` 拼错、或正文里随手一个 `{`）**保存时会被拦住** ——
存下去会让机器人变成「对所有消息都转人工」，而且界面不报错，只会让人以为程序坏了。
（占位语 / 欢迎语 / 非文本应答这几项不参与填充，正文里有花括号无所谓。）

---

## 8. 企业微信 API 模式（可选，门槛更高）

需要准备：

1. 企业微信管理后台的应用/客服 Secret、`corp_id`、`open_kfid`（客服账号 ID，形如 `wk...`）
2. 起回调服务：`python scripts/wecom_callback_server.py --token ... --aes-key ... --corp-id ... --port ...`
3. 一个**能被公网访问**的地址（内网穿透：ngrok / cloudflared），填到后台「API 接收事件」处
4. `.env` 里填 `WECOM_CORP_ID` / `WECOM_KF_SECRET` / `WECOM_OPEN_KFID`

**踩坑记录**：`docs/微信客服API接入.md`（含 corp id 验证、Token 校验、公网 IP 白名单、常见 errcode）

> 拿不到权限或懒得配？**截图模式就是为这种情况做的** —— 它不需要上面任何一项。

## 9. 日常使用与排错

| 想干什么 | 在哪 |
|---|---|
| 看它答了什么 | 主界面记录区；结构化日志 `logs/auto_replies.jsonl` |
| 处理答不准的 | 「**待人工**」页：一条消息一行，可改稿后再发；改完可选「学习」 |
| 让它从人工改稿里学 | 「知识库 → **学到的**」页勾上「**自动学习**」—— **出厂默认关闭**。开启后只自动学语气；改稿里带出的新说法（价格/时效/政策）要人工点「采纳进资料库」才生效 |
| 知道该补什么资料 | 「知识库 → 资料库 → **最常转人工的问题**」：按次数排序，双击一行预填进新增资料 |
| 排错 | **先看 `logs/monitor.log`**（启动过程、报错、每次判断都在里面） |
| 验证改动有没有变坏 | `python scripts/eval_set.py`（46 题评测集，用资料库副本，只生成不发送） |
| 检查有没有泄漏客户数据 | `python scripts/privacy_check.py --path .` |

**常见问题**

| 现象 | 原因 / 处理 |
|---|---|
| 启动闪退 / 报嵌入模型错误 | 没做 §2：`python scripts/prepare_model.py` |
| 报 401 / 模型调用失败 | Key、Base URL、模型名三者对不上；看 `logs/monitor.log` 的具体报错 |
| 界面点开始没反应 / 找不到窗口 | 客户端没登录，或最小化到托盘了；**企业微信窗口要可见** |
| 答得不准 | 先补资料库（见 §6），再考虑改提示词 —— 效果 90% 取决于资料 |
| 它老是转人工 | 正常：资料里没有的它会转人工而不是编。用「最常转人工的问题」补资料即可 |
| 不想让它自动发 | 不填 LLM Key（只转人工），或在设置里关掉自动发送 |
| 隐私担心 | 聊天记录只存本机 `data/context/`；回答时只把「客户这句话 + 命中的资料片段」发给**你自己配置的**模型 |

---

## 10. 打包给别人用

```bat
python scripts/build.py
```

输出 `dist/WeComBot/`（约 1.6GB，含 Python 运行时 + OCR + 嵌入模型）：
对方解压 → 双击 `启动.bat` → 按包里的 `使用说明.txt` 填自己的 Key。
打包流程自带**隐私门禁**：扫到真实凭据 / 客户数据就中止，不会把敏感内容打进去。

# v1.3 — Windows 免安装版（资料库优先 + AI 整理导入）

> 「截图 RPA + 资料库 RAG」自动客服的**免安装分发包**：解压即用，不需要装 Python。
> **这一版是功能版**：把"该不该答"的判断顺序改成**资料库优先**，新增「用 AI 整理成问答」导入，
> 并修掉一批**实机测试报上来**的毛病。已经装了旧版可以覆盖解压，`data/` 目录自己留着。

## 这是什么

给"一个人兼客服的 1–5 人小店"用的自动客服：截屏 + OCR 读聊天软件里的消息，
**只按店主自己上传的资料回答**，价格 / 型号在资料里查不到就**转人工**，
人工改稿确认后它还会学（学到的东西先进「学到的」等你确认，不会自动进资料库）。

本项目**基于开源项目 [zhu-tingshuai/personal_wxwork_ZTS](https://github.com/zhu-tingshuai/personal_wxwork_ZTS)（MIT）改造**；
采集层（截图 / 红点 / 气泡 / OCR）与界面框架来自上游，改造部分见仓库 README「项目来源与我的改造」。

## 怎么用（3 步）

1. 下载 `WeComBot-v1.3-win64.zip` → 解压到任意目录（**路径别太深**）
2. 双击 **启动.bat**（首次启动要加载 OCR 与向量模型，约 30~90 秒）
3. 界面右上「**设置**」→ 填**你自己的**模型接口（API Key / 地址 / 模型名）→ 保存；
   然后选接入通道 → 打开对应软件并登录 → 点「**开始**」

> **没配模型接口就不能「开始」**：点「开始」会被拦下并弹窗送你到「设置」（界面顶部也会常显提示）。
> 详细步骤（资料库用法、提示词、API 模式、常见问题排错）见包内 **`使用说明-详细.md`**。

## v1.3 新增

### 1. 资料库优先于规则层（这一版的核心）

**问题**：客户问「我想修改收货地址」，资料库里**明明有**这条，程序却直接转人工了。

原因是判断顺序：**规则层先判**，判成"订单变更"就转人工，根本没去查资料库。
于是店主不断补资料，也永远替代不了人工 —— 规则层认得出的场景，资料写得再全也轮不到它出场。

**现在**：规则层说"转人工"时，**先看资料库能不能答**（最高分 ≥ 0.75），能答就按资料库答。

* 只对**政策类**原因生效：订单变更 / 发票寄送 / 店内情况 / 政策未覆盖
* **不受影响**（一律转人工）：实时状态（快递到哪了、有没有现货）、
  权限（议价 / 退款 / 投诉）、安全（伪造、要他人信息）

**0.75 这个门槛是测出来的**，不是拍的：

| 门槛 | 放行条数 | 其中答非所问 |
|---|---|---|
| 0.50 | 14 | 13 |
| 0.65 | 6 | 5 |
| **0.75** | **1** | **0** |

答非所问的实测分数上限是 **0.726**；资料库里真有这条时，自命中 **≥ 0.738**（≥0.75 覆盖 99%）。
0.75 正好卡在两者中间。

### 2. 检索不到时，让 LLM 判「业务问题还是闲聊」

规则分类器判不准 **且** 检索分低于 0.50 时，才问一次模型："这句是业务问题还是闲聊？"

* 只有落到这一段的才问 —— 实测 600 条评测里**只有 4 条（1%）**，不是每条都调
* LLM 判不出来（没配 Key / 超时 / 输出没法解析）**一律退回规则结论**，绝不阻塞
* 它是**仲裁不是替代**：实测 LLM 会把「你们老板是男的女的」判成闲聊，
  而那是店主定的转人工 —— 靠规则层的业务信号接住

**默认口径没变**：没有业务词就是闲聊，直接答。

### 3. 「用 AI 整理成问答」导入资料

以前只有"一问一答"格式的资料能被检索到。现在：**知识库 → 资料库 → 用 AI 整理成问答**

粘贴/上传陈述句、表格 → 模型拆成一问一答 → **机器校验**（数字、单位、型号对不上的**标红**）
→ 人工勾选要哪几条 → 写入资料库。

* 超过 100 条会**先弹窗确认**再截断（以前是静默丢掉）
* 命令行原型：`python scripts/llm_ingest.py`
* 资料写法的实测对照（陈述句 / 表格行 / 问答对）见 `docs/资料库上传.md`

### 4. 从人工改稿学习：学到的条目终于能用了

**问题**：店主改稿教了它「索尼 zve10 售价 5000、日租 80、租期 3 天起」，
去资料库搜**搜不到**。两个原因：学到的问题抄的是**客户的原话**（抱怨句），
答案被拆成**三段碎片**，检索时都对不上。

**现在**：学到的条目**合并成一条完整事实**，并另生成一个"客户会怎么问"的问题当检索面。
上面那条现在是：

> 索尼zve10多少钱一天 → 索尼 zve10：售价 5000 元，日租 80 元，租期 3 天起。

检索分 0.936 / 0.749 / 0.737（三种问法都能命中）。

> ★ **出厂默认改成开启**（v1.2.1 是关闭）。开关有三处：
> 「待人工 → 编辑」窗**两个按钮下面**、「知识库 → 学到的」页、`config.json` 的 `kb.learn.enabled`。
> 学到的东西**不会自动进资料库** —— 先进「学到的」等你确认（防口误入库）。

### 5. 界面

* **数据页改成两格**：「待人工」/「已回复」（取消原来永远空着的「全部」）
  * 「已回复」= 软件**所有发出去的消息**：自动回复、占位语、欢迎语、人工代发
  * 从 `logs/auto_replies.jsonl` 读回，**重启不丢**；时间带日期、最新在上
* **「待人工 → 编辑」窗**：两个按钮不再被吞（窗口可缩放，按钮固定钉在底部）；
  「自动学习」开关挪到**两个按钮下面**，就在你改稿的地方
* **窗口置顶改成可配置**：以前是**硬编码置顶**（压在一切窗口之上，关不掉）；现在**默认不置顶**，
  底部「窗口置顶」勾选框随时切换，切换即写回配置、重启也记得
* **资料库翻页修好**（原来是假翻页）+ 搜索改成**全库搜索**（以前只搜当前页，所以"明明有却搜不到"）

## v1.3 修了什么（都是实机报上来的）

| # | 现象 | 根因 |
|---|---|---|
| 1 | **发消息没反应** | 短会话（聊天区只有一两条消息）落在扫描窗口之外被漏掉 → 加宽范围兜底 |
| 2 | **每次都假报"发送失败"** | 发送结果校验里引用了外层作用域不存在的变量（NameError），发送其实成功了 |
| 3 | **扫描崩一次就不再动** | `_scan_fallback` 漏传参数导致 NameError → 已补，并加**静态检查**防止再犯 |
| 4 | **客户又问一遍同一句话，一声不吭** | 去重按**文字**判定"已经回过"，600 秒内第二次问被吞掉；而那个气泡结构上明明是未回复的。两个窗口一起降到 120 秒（只降一层不够，另一层还会接着拦） |
| 5 | **闲聊被误判成业务 → 转人工** | 闲聊信号覆盖不全 → 用评测集 E 组当尺子补齐，漏项 3 条 → 0 |
| 6 | **转人工的回复发了两遍** | 发送后校验误判"还有未回复灰泡" → 改成发送前后对比，只在完全没变化时才重发 |
| 7 | 跑测试会把生产日志写脏 | 测试期日志重定向到临时目录 |

## 发布前自查发现并修掉的两个问题

这两条不是使用者报的，是这次发布前逐项检查时抓到的：

1. **隐私自检漏扫了资料库。** 知识库索引是 sqlite 文件，
   而自检脚本只扫"文本后缀"和"二进制后缀"两类 —— `.sqlite` **两边都不在**，
   于是打包时整个资料库的内容**从来没有被查过**。
   这很危险：`学习` 功能正好会把真实对话学进索引，走这条路就能把客户信息带进分发包。
   现在 `.sqlite / .sqlite3 / .db` 也按字节扫真实姓名与凭据（配了回归测试钉住）。
2. **退出时往日志里打调用栈。** 早前排查"窗口自己关了"时留的调试代码：
   每次退出都往 `logs/monitor.log` 写一段 traceback（看着像崩溃），还多写一个 `logs/close_trace.log`。
   已删除。

## 测试与评测

* 自动化测试 **1647 个**（共收集 1656；默认跳过 9 个：需要真调模型生成问答的 5 个、
  需要嵌入模型的 3 个、会拉起 GUI 的启动冒烟 1 个 —— 分别用
  `RUN_LLM_TESTS=1` / 去掉 `SKIP_EMBED_TESTS` / `RUN_STARTUP_SMOKE=1` 打开。
  另有少数 GUI 用例在拿不到 Tk 显示环境时会自行跳过）
* 含"发错人""内部信号外泄""越权承诺"等真实事故的回归测试
* 三套各 200 条测试消息（`eval/messages_200*.csv`），覆盖八大类：
  **危险直发 0**
* 一键体检：`scripts/eval_messages_200.py`、`threshold_scan.py`、`compare_thresholds.py`
* 打包流程自带**隐私闸门**：扫出真凭据 / 客户姓名 / 开发机路径就直接中止打包

## 运行要求

* Windows 10 / 11 64 位
* 企业微信 PC 版（截图模式）；微信 PC 版需先跑 `scripts/calibrate_chat_app.py` 标定
* 一个 OpenAI 兼容的模型接口（DeepSeek / 通义 / Kimi / 本地 vLLM 皆可）

## 合规说明

* 本程序通过模拟人工操作控制桌面客户端，请确认符合所在平台服务条款与当地法律。
* 客户聊天记录只存在使用者本机 `data/context/`；回答时只把"客户这一句话 + 命中的资料片段"
  发给使用者自己配置的模型接口。
* 分发包里**不含**任何真实客户数据与 API Key；看板示例数据的客户名全部为虚构。

## 从 v1.2.1 升级

覆盖解压即可（**先关掉正在运行的程序**）。`data/` 目录（资料库、客户上下文、待人工队列）自己留着，
新版的 `config.json` 会比旧版多几个键（`kb.kb_first`、`rag.intent_llm`、`ui.always_on_top`）——
**直接覆盖 `config.json` 会把你在设置面板里改过的项还原**，介意的话只覆盖程序文件、保留自己的 `config.json`。

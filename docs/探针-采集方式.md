# 探针报告：企业微信采集方式（抓窗口 / 点击）

**探针**：`scripts/probe_capture_wework.py`、`scripts/probe_click_postmessage.py`
**日期**：2026-09-24　**目标窗口**：`wxwork.exe` `WeWorkWindow` hwnd=394116，2019×1728 @ (0,0)

只读/只点会话列表一行；不抢前台、不移动真实光标、不改窗口状态。

## 结论（三条，都验证过）

| 问题 | 结论 | 证据 |
|---|---|---|
| 能不能不抢前台抓到完整画面？ | **能**。`PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT=2)` | 窗口处于**后台**（`是前台=False`）时抓到 2019×1728，`nonblack_ratio=0.9961`，会话列表与会话气泡文字**全部清晰可读** |
| 能不能不抢前台点击切会话？ | **能**。`PostMessageW(WM_LBUTTONDOWN/UP)` | 点击后聊天区指纹变化、目标会话变成高亮选中态；点回功能栏又能切回来，指纹**确定性复现** |
| 需不需要 DPI 处理？ | **必须**。否则坐标全错 | 未做 DPI 感知时 `GetWindowRect` 返回 `1346×1152`（150% 缩放下的虚拟化坐标），抓出来的不是整窗 |

## 1. PrintWindow 实测

```
hwnd=394116  前台hwnd=198198  是前台=False  最小化=False  可见=True
[print]  调用返回=True 扫描行=1728 区域=(0,0,2019x1728) {'mean': 238.75, 'max': 255, 'nonblack_ratio': 0.9961}
[bitblt] 调用返回=True 扫描行=1728 区域=(0,0,2019x1728) {'mean': 238.75, 'max': 255, 'nonblack_ratio': 0.9961}
```

- `PrintWindow` 在**窗口不是前台**时依然出完整画面 → 采集不再需要 `SetForegroundWindow`。
- `BitBlt` 结果与 `PrintWindow` 完全一致（该时刻窗口未被遮挡）。`BitBlt` 只在窗口可见且未被遮挡时有效，
  所以正式实现用 `PrintWindow`。
- 用视觉模型核对抓到的 PNG：左侧会话列表（客户A@微信 / 客户D@微信 / 邮件提醒 / 客户联系 /
  行业资讯 …）与右侧气泡文字（"租两台可以便宜些吗"、"帮您问下缺不缺保安，稍等。" …）**全部可读**，
  无黑块、无空白。

- 视觉核对第三张截图：左侧某会话行变蓝高亮、右侧打开对应会话 → 点击**真的被业务逻辑处理了**，

  会话列表在更右边（本机约 x≈100–464）。行 y 与会话的对应关系要靠实际探测，别照抄本次数字。

## 3. 踩到的坑

- **`GetDIBits` 少写 `argtypes` 会被当成 32 位参数**，64 位 HDC 直接
  `OverflowError: int too long to convert`。探针里所有 Win32 调用都补了 `argtypes`/`restype`
  （`CLAUDE.md` 里那条"64 位指针截断"的老规矩，这次又踩了一遍）。
- **不做 DPI 感知 → 坐标虚拟化**。抓图尺寸错、点击位置也错。正式实现必须在进程启动最早期
  设 `SetProcessDpiAwareness(2)` / `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`。

## 4. 对任务 2 的直接指导

现在的采集路径是「抢前台 → 移动真实光标点击 → 截屏区域」，三个不稳定源可以同时拿掉：

| 现在 | 改成 | 收益 |
|---|---|---|
| `SetForegroundWindow` + `show/raise` | 不做，直接 `PrintWindow` 抓 `WeWorkWindow` | 不再抢用户焦点、不再闪屏 |
| `SetCursorPos` + `mouse_event` 点会话行 | `PostMessageW(WM_LBUTTONDOWN/UP)` | 不移动真实光标、点击期间用户能继续用电脑 |
| 截整屏再裁区域（可能把自己 GUI 截进去） | 直接抓目标窗口 hwnd | 天然不含自己的窗口，裁剪误差消失 |

配合 jev 那套 OCR 稳定性做法，任务 2 的完整改造清单：

1. PrintWindow 抓 `WeWorkWindow` + PostMessage 点击（本条已探针验证）
2. 进程 DPI 感知（本机 150% 缩放，必须）
3. **帧停稳再 OCR**：连续抓帧，聊天区像素稳定 0.2–0.3s 才送 OCR，跳掉滚动动画/半截气泡
4. **像素锚点自动定位**：底色众数 + 分隔线求 col1/col2 边界，替代写死的 `col1_width_px`/`col2_width_px`
   （窗口宽度已经从 1440 变到 2019，写死必崩）
5. **颜色分边 + 对比度过滤**：绿底=我方、高对比度=对方、灰字（时间戳/引用/系统提示）过滤
6. **RapidOCR（ONNX）替代 PaddleOCR**：解决 `could not execute a primitive` 崩溃
7. **OCR 挪到独立进程**：一帧 OCR 250–800ms，现在跑在 Tk 主循环里会卡住整个界面

## 自验缺口

- `PrintWindow` 只验了"窗口可见但非前台"。**窗口被其他窗口完全遮挡、或最小化**时是否仍出图未验。
  （jev 的经验：最小化时 Windows 不渲染，任何截图法都拿不到画面，他们的做法是
  `ShowWindow(SW_SHOWNOACTIVATE)` + 压到最底层。）
- `PostMessage` 点击只验了会话列表行与功能栏；**向输入框发键盘消息、点发送按钮**未验（也不打算做）。
- 未验多显示器 / 窗口非 (0,0) 位置时的坐标换算（本次窗口恰好贴在 (0,0)，掩盖了偏移问题）。

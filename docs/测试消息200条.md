# 测试消息 200 条（遍历式体检）

46 题评测集（`scripts/eval_set.py`）是"**尺子**"——挑关键路径，用来判断一次改动让回答变好还是变坏。
这 200 条是"**体检**"——把机器人可能遇到的消息类型铺满，看**哪一类会翻车**。

## 文件

| 文件 | 用途 |
| :--- | :--- |
| `scripts/eval_messages_200.py` | 200 条数据 + 导出 + 批量跑 |
| `eval/messages_200.csv` | 带标签的表格（编号/大类/类型/消息/期望行为/参考要点），Excel 可开 |
| `eval/messages_200.txt` | 只有消息正文，一行一条，用于**手工逐条发**给真机 |
| `tests/test_eval_messages_200.py` | 这套题自身的自检（条数、编号唯一、期望值合法、导出正确） |

## 怎么用

```bash
# 1) 只导出表格和纯文本，不调模型（免费）
python scripts/eval_messages_200.py --export

# 2) 先跑 20 条看看
python scripts/eval_messages_200.py --limit 20

# 3) 全跑（约 10~20 分钟，会消耗 API 额度）
python scripts/eval_messages_200.py --out logs/eval_200.json
```

安全性（与 46 题评测集同一条硬约束）：

* Qdrant 用**副本**，不抢运行中程序的锁
* 会话记录与日志**重定向到临时目录**，不污染真实客户历史
* 只**生成**回复，不做任何发送动作——客户收不到任何东西

| 大类 | 条数 | 期望行为 | 说明 |

期望行为合计：**自动答 145 / 转人工 45 / 不该回 10**。

## 判分口径（脚本给结论，对错要人看原文）

跑完输出三段：

* **行为符合期望 N/200**——期望与实际是否一致
* **危险直发**（最严重）——期望"转人工"却发出去了：客户会收到编造的答案
* **该答没答**——期望"自动答"却没答出来：客户体验损失

注意两条口径细节，否则会把"正确设计"误判成翻车：

* D 类期望值是 `auto`：**固定模板婉拒本身可以自动发**（不含任何事实）。真正的错误是"被当玩笑接过去"或"泄露凭据"。
* F 类期望值是 `no_reply`：收尾语、纯符号不回，**既不回也不转人工**——转人工会产生无意义工单。

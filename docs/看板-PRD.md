# 运营看板 PRD（设计稿 · 已实现 MVP）

> 状态：**MVP 已实现**（`stats/aggregate.py` + `gui/dashboard.py` + `gui/theme.py`），
> 主窗口头部新增「数据」按钮 → 独立窗口。视觉依据见 [`UI设计参考.md`](UI设计参考.md)。
> 读者：店主本人（一个人看店、同时兼客服）。

## 〇、需求复述（先确认我理解得对不对）

1. **给谁看**：只有店主自己（不做对外展示形态）
2. **要他看完能干什么**：一眼看到"机器人今天替我做了什么"，以及"**我该补哪条资料**"
3. **入口**：独立窗口（主窗 700×280 塞不下，不动主窗布局）
4. **客户问题怎么分类**：按"这条消息命中了资料库里的**哪份资料**"归类（零成本、可解释）；
   **不做 LLM 打标**（留到 v2）
5. **时间范围**：今日、近 7 天，以及**日历自选起止日期、按天数统计**
6. **本期只做设计**，不写代码

### 已确认的三个口径（2026-10-03）

| 问题 | 结论 |
| --- | --- |
| "一次咨询"怎么算 | **以回复为单位**：机器人发出**一条回复**算一次接待（不按客户消息条数算） |
| 中位响应是否含"转人工时的占位语" | **含**（客户确实收到了回复）；另外单独标一行"人工真答的中位响应" |
| 导出 CSV 是否带客户原话 | **带**，导出时弹窗提示一次"含客户原话，注意不要外发" |

> 口径落地：`接待数 = 机器人成功发出的回复条数`，其中
> `source=auto`（真答）与 `source=hold`（转人工占位语）分别统计；
> `source=greeting`（欢迎语）与 `source=human_edit / human_confirm`（人工发的）
> **不计入接待数**，单独成行 —— 否则欢迎语会虚高接待量、人工改稿会被算成"机器人自动解决"。
> `自动解决率 = source=auto ÷ (source=auto + source=hold)`。

## 一、一句话定位

**店主的运营仪表盘 = 日报 + 待办清单**，不是 BI 工具。
每个数字都要能回答"看到它我要干什么"，否则就是虚荣指标。

## 二、信息架构（一屏，四块，按"结论 → 趋势 → 该做什么 → 它有没有乱来"排）

```
┌ 时间范围：[今日] [近 7 天] [自定义 ▾]        2026-10-03 19:20 刷新 ↻ ┐
├ ① KPI 四卡 ────────────────────────────────────────────────────────┤
│  接待 42 条(11 位客户) │ 自动解决 78% │ 待人工 3(实时) │ 中位响应 1.5s │
├ ② 趋势 ───────────────────────────────────────────────────────────┤
│  柱：每格接待量（粒度随天数自适应）   线：自动解决率                  │
├ ③ 左：客户在问什么 Top10 ────────┬ 右：我该补什么 Top10 ────────────┤
│  押金与支付 12 │ 价格 9 │ 物流 6…  │ 「国庆有货吗」×5  双击→预填新增资料 │

│  越权承诺 3 │ 议价 2 │ 政策未覆盖 1 │ 越界婉拒 4 │ 无信息量 6          │
└ 导出 CSV（当前区间明细）────────────────────────────────────────────┘
```

## 三、时间范围控件（本期重点）

### 3.1 三段式

* `[今日]` —— 今天 00:00 → 现在
* `[近 7 天]` —— 今天往前 7 个自然日（含今天）
* `[自定义 ▾]` —— 点开**日历弹窗**选起止

### 3.2 日历弹窗（自绘，`calendar` 模块 + ttk，零新依赖）

* 月视图，`‹ 2026年10月 ›` 切换月份
* 快捷行：`本月` / `上月` / `近 30 天`
* 交互：**第一次点 = 开始日期，第二次点 = 结束日期**；若第二次早于第一次，自动交换
* 选中的区间高亮；底部实时显示 `已选 2026-09-28 ~ 2026-10-03（6 天）`
* **未来日期置灰不可选**（没有数据）
* `确定` 应用 / `取消` 回退
* 记住上次选择：`data/state/stats_pref.json`

### 3.3 粒度自适应（"按天数统计"的关键）

| 选中天数 | 图表粒度 | 说明 |
| --- | --- | --- |
| 1 天（今日） | **按小时**（24 格） | 看一天里的忙闲分布 |
| 2–14 天 | **按天** | 一根柱一天，轴标日期 |
| 15–90 天 | 按天（柱变细）+ 叠加 7 天移动平均线 | 避免柱子过密 |
| > 90 天 | **按周**聚合 | 轴标"9/28 那周" |

阈值写进 `config.json`（`stats.granularity`），以后可调。

## 四、四块内容与口径（口径必须能复算，这是被之前的教训逼出来的）

### ① KPI 四卡

| 卡片 | 口径 | 数据来源 |
| --- | --- | --- |
| 接待 | **机器人发出的回复条数**（`source=auto` 真答 + `source=hold` 占位语）；欢迎语与人工发出的单独成行 | 决策日志（已补字段） |
| 自动解决率（北极星） | `auto ÷ (auto + hold)` | 决策日志 |
| 待人工 | 当前 `pending` 条数 —— **标"实时"，不随区间变** | `data/state/pending_queue.json` |
| 中位响应 | 客户消息 → 客服回复的两次时间戳差，取**中位数**（不用平均值，长尾骗人）；**含占位语**，另标一行"人工真答" | `data/context/*.jsonl` 配对 |

### ② 趋势

柱 = 每格接待量；线 = 自动解决率。粒度按 §3.3 自适应；鼠标悬停显示该格明细（数量/自动/转人工）。

### ③ 左：客户在问什么（Top 10）

* **归类口径**：这条消息检索命中的**资料文件** → 用它对应的人工可读类名
  （如 `06-押金与支付.txt` → 「押金与支付」）
* 没命中资料的，用规则兜底归类：`越界请求` / `闲聊` / `无信息量` / `投诉纠纷` / `其他`
* 每行：类型 + 条数 + 占比 + 迷你条形图
* **点击某类 → 右下角列出该类客户原话**（最多 50 条，可搜索），让店主看到真实语境

### ④ 右：我该补什么（Top 10 转人工问题）★ 看板的灵魂

* 复用现有 `data/unanswered.json`（字段：`question` / `count` / `reason` / `name` / `first_ts` / `last_ts`）
* 每行：客户原话 + 出现次数 + 转人工原因（置信度不足 / 议价特批 / 政策未覆盖 / 指代不明…）
* **双击 → 打开「新增资料」并把客户原话预填进去**（沿用 `gui/unanswered_dialog.py` 已有的交互）
* 保存后该问题从排行消失 → 形成"看到问题 → 立刻补上"的闭环

### ⑤ 今天我拦下了什么（护栏统计）

分类统计（时间范围内）：`越权承诺` / `拖延话术` / `议价加码` / `政策未覆盖` /
`投诉纠纷` / `指代不明` / `无信息量不回` / `越界婉拒` / `索要他人信息`

* 目的 1（对店主）：确认"它在替我踩刹车"，建立信任
* 目的 2（对自己/面试）：护栏命中是可验证的安全指标，与"危险直发 0"互为印证

### 导出

`导出 CSV`：当前区间的明细（时间 / 客户 / 客户消息 / 处理结果 / 回复内容 / 拦下的原因）。
弹窗提示一次：**"含客户原话，注意不要外发"**。

## 五、数据链路与前置改造

### 5.1 新增聚合层（只读、可单测）

```
stats/
  aggregate.py      只读聚合：输入四个源 → 输出一个结果 dict（纯函数，便于单测）
  cache.py          区间结果缓存 → data/stats_cache/agg_<start>_<end>.json（源文件 mtime 变化即失效）
```

输入源（全部已有）：
`data/context/*.jsonl`（权威会话）、`data/state/pending_queue.json`、
`logs/auto_replies.jsonl`（决策元数据）、`data/unanswered.json`（转人工排行）

看板只读聚合结果 —— **数字口径能被单测钉住**，不会哪天悄悄变了。

### 5.2 前置改造 —— ✅ 已完成（2026-10-03）

实测现状（改之前）：`responder.log_send_result()` 写出的**自动发行**记录里
`customer_message` / `guard_decision` / `guard_reason` **都是空字符串**
（只有转人工和 no_reply 的行有客户原话）。后果：

* 算不出"自动发的这些客户问了什么"→ 问题分布少一半
* 算不出"婉拒模板拦下了哪些越界请求"→ 护栏统计只有一半

已做的改造：

1. `rag/responder.py: log_send_result()` 增加 `customer_message` / `guard_decision` /
   `guard_reason` / `decision_path` / `source` 参数（都有默认值，老调用方式仍可用）
2. `main.py` 发送队列增加**第 5 项「日志上下文」**，把客户原话与护栏判定从生产端透传到落盘；
   打上 `source`：`auto`（机器人真答）/ `hold`（转人工占位语）/ `human_edit`（人工改稿发出）/
   `human_confirm`（人工直发草稿）/ `greeting`（欢迎语）
3. 新增 `decision_path`（`rag/responder.py: decision_path_of()`）：把内部字段归一成看板能直接
   分组的短标签 —— `正常直答 / 越权承诺 / 拖延话术 / 议价加码 / 政策未覆盖 / 库存与档期 /
   指代不明 / 退款与投诉 / 越界婉拒 / 闲聊 / 无信息量/收尾 / 模型要人工 / 置信度不足` 等
4. `_log_reply()`（转人工、不回的行）也补上 `decision_path`

`tests/test_stats_logging.py` 共 23 个用例把字段钉死（含"人工发出的不能被算成自动解决"）。

**兼容**：老日志缺这些字段 → 看板显示"—"，不报错、不补算。

## 六、交互与异常

| 场景 | 处理 |
| --- | --- |
| 首次打开 | 读 jsonl 聚合（当前 163 轮，毫秒级）；超 10 万轮走后台线程 + 进度条 |
| 空数据 | 显示"这段时间没有接待记录"，并给两个排查提示（是否点了开始 / 企业微信是否打开） |
| 刷新 | 打开时自动刷新 + 右上 `刷新 ↻`；**不做秒级实时**（避免和扫描抢 UI） |
| 只读原则 | 看板不修改任何业务数据；唯一写操作是导出 CSV |
| 老版本日志 | 缺字段显示"—"，不崩 |

## 七、明确不做（写进来免得以后被加）

* ❌ 多店对比、实时大屏、客户画像、转化漏斗（一人小店用不上，数据也不支撑）
* ❌ 任何云端上报（隐私底线：数据只在本机）
* ❌ matplotlib / plotly（自绘 canvas 足够；不为看板把包体再撑大）
* ❌ LLM 打标做细分类（v2 再说，MVP 用"命中哪份资料"）

## 八、验收标准（怎么算做完）

1. 切「今日 / 近 7 天 / 自定义」，同一份数据在三种范围下 KPI **自洽**（今日 = 区间为 1 天的特例）
2. 粒度自适应正确：选 1 天出 24 小时格；选 14 天出 14 根柱；选 100 天出周柱
3. 「待补资料」双击能预填新增资料；保存后该问题从排行消失（现有行为不回归）
4. **三张卡的分子/分母都能在日志与 context 里手工复算出来**（口径可审计）
5. 单测：给一份 20 轮的固定样本 jsonl，断言 KPI 与分布的每个数字
6. 不引入新依赖；打包体积增加 < 1 MB

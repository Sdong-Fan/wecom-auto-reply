# 资料库：怎么看、怎么改

对应代码：`rag/kb_tools.py`（读改写）、`rag/kb_history.py`（历史/撤销）、
`gui/kb_dialog.py`（资料库 + 试问一句两页）、`gui/kb_edit.py`（编辑/新增窗）。

## 为什么列表要分两列

库里绝大多数条目是 FAQ 型：

```
客户问题: 索尼A7M4日租多少钱
销售回答: 日租 90 元，押金 4000 元。
```

这就是**一条** chunk（问题和答案在一起，检索时只嵌入问题部分，见
`pipeline/embedder.embed_text_for`）。

如果列表只放一列"资料内容"，Treeview 只显示第一行 —— 用户看到满屏"客户问题"，
以为答案根本没导进来（真发生过）。所以：

- 列表按 **客户问题 / 销售回答** 分列（`kb_tools.split_faq` 拆）
- 非问答格式的整段资料标 `[整段资料]` 前缀、灰字，免得以为"答案怎么没了"
- 列里是截断的（问题 120 字、答案 200 字）；**双击一行**开窗看全文
- 「试问一句」同样两列 —— 检索对了但资料本身答错，照样发错，所以答案必须看得见

## 手动操作（增 / 改 / 删 / 撤销）

| 按钮 | 做什么 |
|---|---|
| 新增一条… | 填一句话问题 + 一句话答案，立刻入库生效 |
| 编辑这条… | 问答分开改；非问答格式给一个大框 |
| 看全文 | 完整原文，不截断 |
| 撤销上次修改 | 退回上一版（连点两次退两步） |
| 删除这条 | 删掉，历史里留一份 |

保存会**重新嵌入并替换**（第一次要加载模型，约 5~10 秒，所以跑后台线程）。

### chunk_id 是内容的 md5，所以"改"＝删旧 + 插新

改内容 → md5 变 → 新 id。`kb_tools.update_entry` 先 `embed_and_store` 新文本
（和导入完全同一条嵌入路径），再删旧点；文本没变时**不删**（否则会把自己删掉）。

### 历史挂在"改完之后的新 id"上

这样列表里选中一行就能直接撤销它（选中的是新 id）。
撤销会把文本换回旧内容 → chunk_id 又变回改之前的 id → 所以**连点两次撤销能退两步**
（`tests/test_kb_edit.py::test_undo_twice_walks_back_two_steps`）。

每个条目只留最近 `kb.history_versions` 条（默认 5，配置里可改），存在
`data/kb_history.jsonl`。单行写坏了只丢那一行，不会把整段历史带崩。

## 「最常转人工的问题」＝ 资料库的缺口清单

资料库页上的按钮，打开 `gui/unanswered_dialog.py`。

机器人答不上来就转人工，**转人工＝资料库里没写这条**。这些消息原来只躺在
「待人工」里，人工处理完就没了 —— 同样的问题明天还会再来一次。

| 列 | 意思 |
|---|---|
| 转人工次数 | 排最前面的最值得补（补一条能少转好多次） |
| 客户问的 | 客户原话（按问题指纹合并："房租多少钱？" 和 "房租多少钱" 算一条） |
| 为什么转 | 资料库没找到 / 资料里有但没把握 / 回答里的数字资料里没有 / 答成了套话 |
| 最近一次 | 最后一次发生的时间 |
| 状态 | 待补 / 已补 |

* **加进资料库…**（或双击一行）：把这句话**预填进新增资料的「客户问题」框**，
  你只写答案 —— 不用手打一遍客户原话
* 保存成功后自动标「已补」；如果**同一个问题又转人工了**，会自动退回「待补」
  （说明那条资料没解决问题，得再看一眼）
* 「清空统计」只清这个排行，不动资料库、不动「待人工」

统计写在 `data/unanswered.json`（全局，跟资料库档案无关）。
三个记录点：`main.py` 两条扫描路径 + `gateway/api_policy.py` 的 escalate 分支。

## 陈述句 / 表格能不能直接导？（能，但有讲究）

**结论：能直接用，不必强行改成问答。** 实测同一段内容（索尼A7M4 日租 90 / 押金 4000 /
3300 万像素 / 4K60）用 4 种写法存进库，再用真实问句去查，最高余弦：

| 客户问句 | ① 问答式 | ② 陈述句 | ③ 属性冒号式 | ④ 竖线表格行 |
|---|---|---|---|---|
| 索尼A7M4一天多少钱 | **0.941** | 0.724 | 0.729 | 0.701 |
| A7M4日租多少 | 0.685 | **0.721** | 0.720 | 0.555 |
| A7M4押金多少 | 0.660 | **0.675** | 0.654 | 0.631 |
| A7M4像素是多少 | **0.641** | 0.569 | 0.565 | 0.685 |
| A7M4能拍4K吗 | 0.611 | 0.584 | 0.588 | **0.685** |
| 大疆Air3多少钱（库里没有） | 0.540 | **0.485** ✗ | 0.479 ✗ | 0.525 |

自动答门槛是 **0.50**（`rag.high_confidence_threshold`）。

**怎么读这张表：**

1. 问答式的优势**只在"问句和资料里的问题一字不差"时**（0.941）。
   客户换个说法（"A7M4日租多少"），陈述句反而更高（0.721 vs 0.685）。
2. 所以：**陈述句当底料，高频问法补问答**是最优组合 ——
   高频问法用问答式收口（因为问答型**只嵌入"问题"部分**，见 `pipeline/embedder.py::embed_text_for`），
   长尾事实用陈述句铺开。
3. 三种陈述写法互有胜负，**别丢主语和属性名**是共同点：
   `索尼A7M4 | 90 | 4000` 比光写 `90 / 4000` 强得多（后者连问的是哪台都不知道）。
4. 表格导入会自动转成自然句：`pipeline/upload.py::_row_sentence` 把
   `a | 120 | 2000` 变成 `a：日租（一天）120，押金 2000` ——
   代码注释里有实测：竖线拼接 0.68 vs 自然句 0.75，0.68 就在门槛附近晃，
   换个问法就掉下去。所以**表格直接传就行，管线会帮你改写**。

**格式陷阱（手写时最常踩）：** 只有**精确**以 `客户问题: ` 开头、第二行以 `销售回答: `
开头（`rag/kb_tools.py` 的 `Q_MARK` / `A_MARK`，冒号是**半角 + 一个空格**）才会被当成
问答型、只嵌入问题部分。手写成 `问：… / 答：…`、`Q: … / A: …` 会被当成**整段资料**
整段嵌入 —— 不是不能用，但会失去"问句对问句"的召回优势。

## 已知的资料质量问题（需要用编辑功能修）

原导入管线（`local_pipeline`）里有答非所问的条目，例如：

- 「无人机能租吗」→ 答案是**配件租金表**（稳定器、闪光灯、麦克风…），不是无人机的价格

这类只能手动改。改完去「试问一句」用客户的真实问法验证分数和答案。

## 让 LLM 把资料整理成问答（AI 整理导入）

"导进去一堆陈述句/表格 → LLM 分析 → 整理成资料库问答" 这件事**能做**，两条路：

**① 界面上（推荐）**：知识库页 → 「**用 AI 整理成问答…**」→ 选一个文件 →
弹出预览窗口：每条问答一行、**校验不过的标红且默认不勾选**，
双击一行能看"这条是从哪段原文来的"。勾好再点「写入选中项」。

**② 命令行**（默认只打印不写库，适合先试）：

```bash
python scripts/llm_ingest.py --file 你的资料.txt            # 看整理结果（不写库）
python scripts/llm_ingest.py --file 你的资料.xlsx --write    # 核对没问题再写
```

实测：443 字的陈述句文档 → **30 条问答，校验 0 误杀**。

> 一次只整理**一个文件**：写入时 `source` 要精确等于文件名
> （`pipeline.upload.delete_source_points` 靠它删索引），
> 混多个文件就说不清某条是哪个文件来的，出问题也没法回滚。
> AI 整理写入的条目带 `origin=AI整理` 标记，跟"原文照搬"的条目区分得开。
>
> **大文件会截断，但一定会告诉你**：一块 = 一次 AI 调用，默认只整理前 **100 块**
> （表格上限 5000 行，全量跑要几小时）。开始前先确认一次，
> 结束后状态栏也会写"另有 N 块未整理"。想全量就拆成几个文件分批来 ——
> **静默只导一半是最坑的**，所以宁可啰嗦。

**为什么不能"直接让 LLM 写完就入库"**，三个实测出来的坑：

1. **数字会被改**：LLM 可能把 `4000` 写成 `40000`、"日租"写成"月租"。
   更麻烦的是 —— 写进库之后，护栏"数字必须有出处"会**把被污染的库当依据**，
   错误被系统性地合法化。所以脚本逐条校验：回答里的每个数字都必须能在**原文**里找到。
2. **只比裸数字不够**：`押金 4000 元，即 4 万元？` 能骗过裸数字校验（"4"在 4000 里出现过）。
   要按「**数字+单位**」比 —— "4 万"在原文里不存在，就被拦下。
3. **校验器自己也会误判**：`A7M4 日租` 里的 `4` + `日` 被读成单位配对「4日」，
   把正常答案误杀。加后行断言（数字不能紧跟在字母后面）修掉。
   这两条都已写成回归测试（`tests/test_llm_ingest.py`）。

**已知拦不住的**：纯文字幻觉。例如原文没有库存信息，LLM 却答
`有现货，明天就能发` —— 没有数字也没有型号，自动校验抓不到。
所以流程必须是 **`LLM 整理 → 自动校验 → 人工过一眼 → 写入`**，不能省掉人工那一步。

> 在相机租赁这种"错一个价格就是事故"的场景里，LLM 的价值不是"省录入时间"，
> 而是**给每条事实补上"客户会怎么问"的问法** —— 因为问答型只嵌入问题部分，
> 这正好补上"客户换个说法就召不回"的短板。
> （实测：生成问法后「索尼a7m4像素是多少」能召回 0.875；
> 但「可以到店取货吗」对「可以自提吗？」仍是 0.0 —— 生成问法也不是万能的。）

## 还没做

**一句话修改资料库**：输入「A7M4 日租改成 100」，AI 找出相关条目 → 出 diff →
逐条确认（数字类高亮）→ 写入。设计已确认（历史版本默认 5 版、整体确认、
保留上传副本），历史/撤销这套地基已经就位，接上 LLM 改写 + diff 界面即可。

# 资料库档案（多个独立资料库）

对应代码：`rag/archives.py`（清单与路径）、`gui/kb_dialog.py`（档案栏）。

## 一句话

一个程序里放**多个互相独立的资料库**，像档案夹一样：可以新建、切换、复制、删除。
切了立刻生效，机器人下一条回复就按新库回答。

## 核心设计：第一个档案＝老库原样

| 东西 | 第一个档案（从老库升上来） | 新建的档案 |
|---|---|---|
| 向量 | `knowledge_base` | `kb_<id>` |
| 上传的源文件 | `data/chat_raw/uploaded/` | `data/chat_raw/archives/<id>/` |
| 提示词 | `prompts/` | `prompts/<id>/` |
| 学到的语气 | `data/learned/` | `data/learned/<id>/` |
| 改动历史 | `data/kb_history.jsonl` | `data/kb_history_<id>.jsonl` |

**第一个档案沿用老路径是刻意的**：现有 237 条资料、上传过的文件、改过的提示词
一个字都不搬 —— 迁移越少，出事的可能越小。老用户什么都不做，程序照旧跑；
连清单文件都不会凭空多出来（`load()` 在没有文件时返回一个临时的默认清单，不写盘）。

清单文件 `data/kb/archives.json`：

```json
{
  "active": "photo",
  "archives": [
    {"id": "photo", "name": "摄影器材租赁", "collection": "knowledge_base"},
    {"id": "kb1",   "name": "服装租赁",     "collection": "kb1"}
  ]
}
```

* `active` 放这里（不放 config.json）：档案元数据集中一处，读的时候一次搞定
* 中文名字没法当目录名 → `slug()` 取 ASCII 部分，取不到就用 `kb1`、`kb2` 序号
* 清单被手改坏了 → `load()` 退回第一个档案，程序照常起来

## 独立性（最要紧的一条）

**A 库的问题绝不能检索到 B 库的资料** —— 串味意味着拿服装的价格回答摄影客户，
比不回答严重得多。所以：

* 每个档案一个 collection，检索时按当前档案取
* `rag/retriever.active_collection()` **每次调用现读**（回复路径也是），
  所以界面上切了档案下一条回复就生效，不用重启
* `kb_tools` / `embedder` / `upload` / `learn` 的 `collection` 默认值全部改成
  "当前档案"，而不是写死 `knowledge_base`
* `source_files()`（重建索引的源清单）**只在第一个档案**才带上
  `data/chat_raw/*.txt` —— 那些是老导入管线的源，在"服装租赁"点重建索引
  绝不能把摄影的资料灌进去

回归测试：`tests/test_archives.py::test_no_cross_archive_bleed`
（切到服装档案后问摄影的问题，必须 0 条结果）。

## 界面

档案栏在**标签页上面**，四页都看得见当前在哪个库：

```
┌ 资料库档案（每个档案互不影响，切了立刻生效）
│ [摄影器材租赁 ▾]  [新建] [重命名] [复制档案] [删除]   共 2 个档案｜当前：摄影器材租赁
├ 提示词 │ 资料库 │ 试问一句 │ 学到的
```

* **切换**：改清单里的 `active` → 四页全部重刷（提示词、资料列表、学到的、
  试问一句的提示）。对话框标题也变成「知识库 —— 摄影器材租赁」
* **新建**：填空档案 + **拷当前档案的提示词和语气样本**（说话方式沿用，事实从零开始）
* **复制档案**：连资料条目（**连向量一起拷**，不重新嵌入 → 一两秒、打分完全一致）
  + 源文件 + 提示词 + 语气，拿来做变体最省事
* **删除**：条目删掉，源文件/提示词/历史**挪到 `data/kb/deleted/`**（不真删）；
  两个拦路的检查 ——「只剩一个不让删」（删光就没库可用）、
  「当前正在用的不让删」（先切走再删）

## 踩过的坑

* **重建索引的源清单**：原来无条件把 `chat_raw/*.txt` 算进去，别的档案点重建
  会把老库的资料导入进来。已按 `is_first()` 收口。
* **collection 名叠前缀**：中文档案名走序号 id（`kb1`），拼 collection 时又加了
  `kb_` 前缀 → `kb_kb1`。现在 `collection_name()` 判断 id 已以 `kb` 开头就不再加。
* **删除检查顺序**：只剩一个档案时它必然正在被用，先报"至少要留一个"才说得通
  （先报"正在用"会让人以为"切走就能删"，切走也删不掉）。

## 验证（拿真实的 237 条跑过）

复制一份线上 qdrant 做的端到端验证：

```
1. 第一个档案＝老库原样：摄影器材租赁 / knowledge_base / 237 条 / 老路径
2. 新建「服装租赁」→ collection kb1，0 条
3. 在服装库问「索尼A7M4一天多少钱」→ 0 条结果（没串味）
   切回摄影库 → 0.941 命中「索尼 A7M4一天多少钱」
4. 复制档案 → 237 条连向量一起拷，副本里试问同样 0.941（打分一致）
5. 删副本 → 摄影库还是 237 条，服装库还在，副本目录挪进回收站
```

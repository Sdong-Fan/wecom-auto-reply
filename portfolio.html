一句话

  • 给"一个人兼客服的 1–5 人小店"做一套不用改代码就能接入的自动客服： 截屏读企业微信消息，只按店主自己上传的资料回答，价格与型号在资料里查不到就转人工， 人工改稿确认后它还会学。

问题（为什么要做）

  • 小店老板绝大多数咨询是重复的：实测真实客户消息 99%（76/77）集中在 7 类问题上 （押金/免押、营业时间、机型库存、租赁规则等）。
  • 通用客服 SaaS 要么要企业认证 + 开发对接，要么按坐席收费（同类产品客服名额约 550 元/客服/年）—— 对一个人看店的小店都不成立。
  • 结果：老板一边干活一边手打回复，响应慢一点就丢单。

目标用户

  • 第一优先：1–5 人、店主本人兼客服的小店/工作室（无 IT 支持、拿不到 API 权限、 问题重复且答案固定）。
  • 不做：中大型企业 —— 他们要权限、审计、SLA，选型逻辑完全不同。

产品与链路

  • 形态：装在本机 Windows 上的桌面端自动客服（不改客户端、不要 API 资质、免安装）。
  • 链路：截屏识别新消息 → 判断该不该答 → 检索店主自有资料库 → 生成回复 → 三态质量门控（直发 / 降级 / 转人工）→ 待人工工作台改稿后学习 → "最常转人工的问题"排行回流指导补资料，形成闭环。
  • 三条关键机制：① 回复中的价格与型号必须在资料库中有出处，否则拦下转人工； ② 越界请求（套取凭据、背诗、算长算式）按模板婉拒；③ 发送前确认会话名防发错人。

我的角色

  • 本项目基于开源项目 zhu-tingshuai/personal_wxwork_ZTS（MIT 许可）改造： 采集层（截图 / 红点 / 气泡 / OCR）与界面框架来自上游，原始版权声明按 MIT 要求完整保留。
  • 我负责的五块：① 定义"什么时候不能答"并落地护栏；② 建立评测与指标体系（46 题评测集 + 阈值扫描）； ③ 设计人机学习闭环；④ 发送链路安全；⑤ 交付与隐私（打包隐私门禁、免安装分发）。

怎么自己跑（3 步）

  1. 解压免安装包（Windows，下载约 850 MB，解压后约 1.6 GB）→ 双击 启动.bat（首次启动加载模型约 30–90 秒）
  2. 界面右上「设置」→ 填你自己的模型接口（API Key / 地址 / 模型名）→ 保存
  3. 选「企业微信 · 截图模式」→ 打开企业微信 PC 版并登录 → 点「开始」

不填 Key 也能开：此时机器人不自动回复，只把消息转「待人工」，不向任何地方外发内容。
